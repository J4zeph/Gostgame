# work-report

Пользователь не видит вывод инструментов и не читает дифф. Отчёт - единственное, по чему он судит о результате. Пиши его сам (оркестратор), не делегируй: он держится на контексте всей работы.

## Формат

```
## Итог
<одна строка: готово / частично / заблокировано + главное>

## Получилось
- <что сделано> - <пруф: файл, команда, коммит>

## Не получилось / не сделано
- <что> - <почему> - <что нужно, чтобы доделать>
(если всё сделано - "Всё из запроса выполнено", раздел не опускать)

## Проверка
<цифры из Logs\verify\summary.txt: compile / editmode / playmode, RESULT>

## Изменения
- Файлы: <ключевые новые/изменённые, путями>
- Пакеты: <что добавлено/изменено, версии> (если были)
- Git: <коммит hash, запушено или нет>

## Нужно от тебя
- <решение / действие с вопросом, на который можно ответить одним словом>
(нет - "Ничего")

## Дальше
<1-3 пункта, первый - рекомендуемый следующий шаг>
```

## Правила

- **Честность важнее красоты.** Не сделал - в «Не получилось». Не проверил - так и пиши «не проверено», а не «должно работать».
- **«Готово» = verify зелёный.** Если verify не запускался или красный, итог не может быть «готово».
- **Каждый пункт «Получилось» с пруфом** - путь к файлу, вывод команды, хеш коммита. Без пруфа это обещание, а не результат.
- **Отклонения от запроса** (сделал иначе, чем просили, или добавил то, о чём не просили) - отдельной строкой в «Получилось» с причиной.
- **Блокеры** (проект открыт в Unity, нет согласия на пакет, нет доступа) - в «Нужно от тебя» с конкретным действием.
- Коротко: весь отчёт помещается на экран. Детали - ссылкой на файл (`Logs\verify\summary.txt`, лог), а не простынёй.
- Язык - русский, без внутреннего жаргона агентов; термины проекта (asmdef, NGO, Relay) - можно.
- Отчёт по шагам (если пользователь просил «отчитывайся после каждого шага») - короткие строки по ходу работы, этот формат - в конце.
