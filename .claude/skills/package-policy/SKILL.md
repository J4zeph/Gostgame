# package-policy

Пакеты меняет только пользователь - агент предлагает и ставит **после явного согласия**. Правило из CLAUDE.md: «Добавлять или обновлять пакеты без согласия пользователя - запрещено». Этот скилл - как именно это соблюдать.

## Реестр одобренных пакетов

Единственный источник правды. Пакета нет в таблице = согласия нет. После согласия пользователя - сначала строка сюда, потом установка.

| Пакет | Версия | Зачем | Одобрено |
|---|---|---|---|
| Пакеты шаблона Universal 3D (URP, Input System, uGUI, Test Framework, IDE, Collab, `com.unity.modules.*`) | как в manifest на 2026-11-01 | база проекта | шаблон |
| `com.unity.netcode.gameobjects` | 2.13.3 | мультиплеер (NGO) | 2026-11-01 |
| `com.unity.multiplayer.playmode` | 3.0.0 | второй игрок в редакторе без сборки | 2026-11-01 |

Ожидаются по плану, но **ещё НЕ одобрены** (спросить, когда дойдём): Unity Relay/Lobby (`com.unity.services.multiplayer`), Vivox.

## Что требует согласия (стоп и спросить)

- Новый пакет - любой, включая официальные Unity и встроенные `com.unity.modules.*`.
- Смена версии одобренного пакета (вверх или вниз) и удаление пакета.
- Источник не из реестра Unity: git URL, локальный путь (`file:`), `.tgz`, scoped registry (OpenUPM и т.п.).
- Ассет из Asset Store или любой сторонний код/контент (только в `Assets/ThirdParty/`).
- Ссылка asmdef на сборку пакета, если её нет в таблице сборок CLAUDE.md (например, `Game.UI` -> `Unity.TextMeshPro`). `Game.Network` -> `Unity.Netcode.*` / `Unity.Services.*` уже разрешено таблицей.

## Что запрещено даже с согласием без отдельного обсуждения

- Preview / experimental / pre-release версии (`-pre`, `-exp`, `0.x`) - только если пользователь явно согласился именно на такую версию и понимает риск.
- Пакет, требующий другой версии Unity, или смена версии редактора (стек в CLAUDE.md).
- Сторонний пакет без понятной лицензии.

## Можно без согласия

- Читать manifest, lock, реестр Unity, документацию пакетов.
- Изменения `packages-lock.json`, которые Unity сделала сама при разрешении уже одобренных пакетов, - коммитить вместе с изменением, которое их вызвало, и упомянуть в отчёте.

## Как спросить согласие

Одним сообщением (или AskUserQuestion), чтобы пользователь мог решить сразу:

1. Пакет и точная версия.
2. Зачем - какая задача без него не решается.
3. Альтернативы, включая «без пакета, своим кодом», и почему хуже.
4. Цена: зависимости, которые он притянет; preview или нет; лицензия (для стороннего).
5. Что поменяется в проекте: manifest, lock, какие asmdef получат ссылку.

Нет ответа = нет установки. Задачу, которой нужен пакет, ставь на паузу и отчитайся о блокере.

## Как ставить после согласия

1. Добавь строку в реестр выше (пакет, версия, зачем, дата).
2. Версия: для пакетов Unity бери рекомендованную для редактора из
   `C:\Program Files\Unity\Hub\Editor\6000.6.7f1\Editor\Data\Resources\PackageManager\Editor\manifest.json` (поле `version` у пакета). Не «последнюю с сайта».
3. Добавь строку в `Packages/manifest.json` -> `dependencies` (алфавитный порядок). Это единственный файл из запрещённых в CLAUDE.md, который можно править руками, и только по согласию.
4. asmdef - ссылку только туда, где она разрешена таблицей CLAUDE.md.
5. Прогони `unity-verify` (`Tools\verify.ps1 all`): Unity сама скачает пакет и обновит `packages-lock.json`. Зелёный - готово.
6. Коммит: `manifest.json` + `packages-lock.json` + реестр в этом файле + asmdef - одним коммитом.

## Отчёт

По скиллу `work-report`: какой пакет и версия встали (из `packages-lock.json`), какие зависимости притянулись, результат verify.

## Для оркестратора

Субагент, которому для задачи «нужен пакет», не ставит его сам: возвращает эскалацию (что за пакет и зачем). Решение и вопрос пользователю - за оркестратором. Путь к этому файлу - в каждый промпт субагента, который может коснуться пакетов или asmdef.
