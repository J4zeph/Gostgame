# Правила проекта: кооп-хоррор (охота на призраков, в духе Phasmophobia)

Эти правила обязательны для главного агента и для каждого субагента, который пишет или правит код. Перед сдачей работы сверь свой дифф с этим файлом.

## Стек (не менять без решения пользователя)

- Unity 6.6 (6000.6.7f1), рендер URP (шаблон Universal 3D). Обновляемся только внутри линейки Unity 6 и только по решению пользователя
- Мультиплеер: Netcode for GameObjects (NGO) + Unity Relay + Lobby; голос позже (Vivox)
- Схема: один игрок хостит (host = server + client), остальные подключаются через Relay. Выделенного сервера нет
- Разработка на Windows, Git + Git LFS

## Структура папок

```
Assets/
  _Game/                    <- весь наш код и контент, сторонние ассеты НЕ сюда
    Scripts/
      Core/                 <- чистая логика: правила, состояния, расчёты. Без MonoBehaviour где возможно
      Gameplay/             <- Ghost/, Evidence/, Equipment/, Player/, Interaction/, Settings/ (пользовательские настройки)
      Network/              <- NetworkBehaviour-адаптеры, RPC, синхронизация, Relay/Lobby
      UI/
      Audio/
      Editor/               <- editor-скрипты: создание сцен/префабов, инструменты, сборка
    Data/                   <- ScriptableObject-ассеты: типы призраков, снаряжение, улики, баланс
    Prefabs/
    Scenes/
    Art/  Audio/
  Tests/
    EditMode/
    PlayMode/
  ThirdParty/               <- ассеты из Asset Store и сторонние пакеты
```

## Assembly definitions (границы зашиты в компиляцию)

|---|---|---|

| `Game.Gameplay` | Core, Unity.InputSystem (только для чтения ввода, `Gameplay/Player/PlayerInputReader`) | **Netcode**, UI |
| `Game.Network` | Core, Gameplay, Unity.Netcode.* , Unity.Services.* | UI |

## Главное архитектурное правило: сеть - тонкий слой

- Игровая логика (призрак, улики, снаряжение, охота) живёт в `Core`/`Gameplay` и **ничего не знает о NGO**. Она выставляет состояние и события.
- `Network/` синхронизирует это состояние: NetworkVariable, RPC, спавн NetworkObject. Логику туда не пишем.
- Цель: смена сетевой библиотеки = замена папки `Network/`, а не переписывание игры.

## Сетевые правила (NGO)

- **Авторитет у хоста.** ИИ призрака, улики, начало и конец охоты, таймеры, рандом решаются только на хосте. Клиенты не принимают игровых решений.
- Клиент присылает **запрос** (RPC на сервер), хост проверяет и меняет состояние. Клиентским данным не доверять.
- Для RPC используй универсальный атрибут `[Rpc(SendTo.Server)]` / `[Rpc(SendTo.ClientsAndHost)]` и т.п.
- Постоянное состояние (позиция призрака, открыта ли дверь, заряд предмета) - через `NetworkVariable` с записью только сервером. Разовые эффекты (звук, вспышка) - через RPC на клиентов.
- Сцены грузит только хост через `NetworkManager.SceneManager`.
- Каждый сетевой префаб должен быть в списке префабов NetworkManager.

## Данные

- Типы призраков, снаряжение, улики, параметры баланса - ScriptableObject в `_Game/Data/`. Никаких магических чисел в коде.
- Новая сущность (новый призрак, новый предмет) = новый ассет данных, по возможности без нового кода.

## ЗАПРЕЩЕНО агентам

- Править вручную `.unity`, `.prefab`, `.asset`, `.mat`, `.meta`, `ProjectSettings/*`. Это сериализованный YAML с GUID-ссылками, ручная правка ломает связи.
- Удалять или переименовывать `.meta` отдельно от файла. Файл переносится только вместе с его `.meta`.
- Трогать `Library/`, `Temp/`, `Logs/`, `UserSettings/`.
- Добавлять, обновлять или удалять пакеты (`Packages/manifest.json`) без согласия пользователя. Реестр одобренных пакетов и порядок установки - в скилле `package-policy`. Shell-командам эти файлы запрещены хуком, правка - только инструментом Edit с подтверждением пользователя.
- Запрашивать подтверждение без объяснения. Перед любым действием, на которое всплывёт запрос подтверждения, - сначала сообщение пользователю: какой файл или команда, что меняется и зачем.

**Как тогда менять сцены и префабы:** пишешь editor-скрипт в `_Game/Scripts/Editor/` (пункт меню `Tools/...` или статический метод для `-executeMethod`), который создаёт или настраивает объект через API Unity. Пользователь запускает его из меню, или он запускается в batchmode.

## Стиль C#

- Пространства имён `Game.<Сборка>.<Подпапка>`, один публичный тип на файл, имя файла = имя типа.
- `PascalCase` для типов, методов, свойств; `_camelCase` для приватных полей.
- В инспектор - через `[SerializeField] private`, а не `public` поля.
- Не использовать `?.` и `??` на объектах `UnityEngine.Object` (у них переопределённое сравнение с null).
- В `Update`/`FixedUpdate`: никаких `Find*`, `GetComponent` без кэша, LINQ и аллокаций. Кэшируй ссылки в `Awake`.
- События и подписки вместо опроса каждый кадр. Отписываться в `OnDisable`/`OnDestroy`.
- Синглтоны - только для явных менеджеров с понятной инициализацией, не по привычке.
- Комментарии - по делу, без истории правок и пометок «изменено агентом».

## Тесты и проверка

- Каждое новое игровое правило в `Core`/`Gameplay` покрывается EditMode-тестом (быстрые, без сцены).
- PlayMode-тесты - для того, что требует сцены, физики или сети.
- Работа считается готовой, только когда проект компилируется без ошибок и тесты зелёные. Команды проверки - в скилле `unity-verify` (`Tools\verify.ps1`).
- В конце задачи - итоговый отчёт пользователю по скиллу `work-report`: что получилось, что нет, цифры проверки, что нужно от пользователя.
- Batchmode не запустится, пока проект открыт в редакторе (Unity блокирует проект). Если редактор открыт - сообщи пользователю, не пытайся обойти блокировку.

## Git

- `.meta` всегда коммитятся вместе с файлами.
- Бинарные ассеты (текстуры, модели, звук) - через Git LFS.
- Не коммитить `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `Builds/`.
